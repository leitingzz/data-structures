# 哈希表操作练习（链地址法，C语言实现）

用C语言实现的哈希表，基于链地址法（拉链法）解决哈希冲突，底层复用链表结构。支持插入、查找、删除、打印四个操作，均可通过命令行菜单交互测试。

## 功能列表

- 插入数据（哈希到对应格子，链表头插法处理冲突）
- 查找数据（定位到格子后遍历链表比对）
- 删除数据（定位到格子后在链表中查找并删除，处理头节点/中间节点/末尾节点/不存在四种情况）
- 打印哈希表（遍历所有格子，展示每个格子内挂载的链表内容，便于调试观察整体分布）

## 设计说明

- 哈希表本质是一个固定大小（`NUM=10`）的指针数组，每个元素是一条链表的头指针
- 哈希函数：`data % NUM`，若结果为负数（C语言中负数取模结果符号跟随被除数）则加上 `NUM` 修正到合法下标范围内
- 冲突处理采用**链地址法**：哈希到同一格子的多个值，以链表形式挂在该格子上，插入使用头插法，查找/删除需要遍历该链表

## 技术要点

- 哈希函数只写一份（`hashFunc`），插入、查找、删除三个操作全部复用它计算下标，避免了"多处重复计算、其中一处漏改导致逻辑不一致"的问题——这类重复逻辑一旦复制粘贴到两处以上，只要有一处遗漏同步修改，就会导致同一个值在插入和查找时被算到不同的格子里
- `delete` 函数在链表内部用循环查找目标节点时，找到并删除后必须立即 `return`（或 `break`），否则循环会继续用一个已经被 `free` 的指针去做下一轮比较，属于典型的 use-after-free

## 开发过程中踩过的坑（简单记录）

- `data % 10` 对负数取模，结果符号跟随被除数（如 `-5 % 10` 结果是 `-5` 而非 `5`），直接用作数组下标会导致越界访问；需要在结果为负时手动加上 `NUM` 修正
- 插入时用了修正过的哈希函数，但查找时最初漏了同样的修正逻辑，导致同一个负数在插入和查找时被映射到不同下标，出现"明明插入过却查不到"的现象——后续将哈希计算抽成独立函数 `hashFunc`，从根源上避免了这类不一致
- `delete` 函数最初用 `while` 循环遍历链表查找目标节点，删除成功后没有 `return`，导致循环继续拿一个已经被 `free` 的指针去做下一轮判断（use-after-free），同时还会在删除成功后额外打印一条"该数据不存在"的矛盾提示
- 变量命名一度用了 `new` 作为新节点的变量名——`new` 在C语言中不是保留字，能正常编译，但它是C++关键字，若代码被迁移到C++环境编译会直接报错，后续统一改成了 `newNode`
