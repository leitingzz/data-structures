# 二叉搜索树操作与经典算法练习（C语言实现）

用C语言实现的二叉搜索树（BST）工具集，涵盖建树、四种遍历方式、以及几道树相关的经典应用题。所有功能均可通过命令行菜单交互测试。

## 功能列表

**建树**
- 插入节点（按BST规则：小于当前节点插左子树，否则插右子树）

**四种遍历**
- 前序遍历（根→左→右）
- 中序遍历（左→根→右）—— 对BST而言结果一定是升序排列，可用于快速验证建树是否正确
- 后序遍历（左→右→根）
- 层序遍历（自顶向下逐层遍历，基于自行实现的链式队列）

**应用题**
- 统计节点总数
- 求树的高度
- 按值查找（利用BST有序性，无需遍历全树）
- 判断是否为合法二叉搜索树（递归传递取值区间，而非仅比较相邻节点）

## 技术要点

- `insert` 使用递归实现，子递归调用的返回值需要重新赋值接回 `root->left` / `root->right`，这是递归修改树结构时最容易遗漏的一步
- 层序遍历基于自行实现的**链式队列**（`enqueue` / `dequeue`），队列节点存储 `TreeNode*`。`enqueue` 会跳过 `NULL` 节点，避免空指针入队；`dequeue` 在返回数据前完成 `free`，遵循"先读后放"的顺序，避免访问已释放内存
- `getHeight` 初版实现中，同一子树的高度在一次函数体内被重复递归调用两次，属于指数级重复计算；优化后先将左右子树高度分别存入变量，再进行比较，降为线性时间复杂度
- `isValidBST` 是这几道题里唯一需要**传递上下文（取值区间）**的递归：不能只比较父子节点，需要维护一个不断收窄的 `(min, max)` 区间，确保子树中的任意节点都满足所有祖先节点划定的约束，而不仅仅是直接父节点的约束

## 开发过程中踩过的坑（简单记录）

- `typedef struct TreeNode{ TreeNode* left; ... }` —— `typedef` 起的别名在语句结束前不可用，结构体内部自引用必须写成 `struct TreeNode* left`，而不能直接用 `TreeNode* left`
- `insert(root->left, value);` —— 递归调用后忘记把返回值接回 `root->left`，导致插入操作实际上什么都没改变（这是理解递归"如何修改结构"的关键一步）
- `min < root->data < max` —— C语言中比较运算符从左到右结合，这行代码实际执行的是 `(min < root->data) < max`，并不能正确判断"data 是否落在区间内"，必须拆成 `min < root->data && root->data < max`
- 在 `isValidBSTHelper` 中检查完当前节点后直接 `return`，导致后面递归检查左右子树的代码变成永远不会执行的死代码；需要先把各部分结果存入变量，最后统一用 `&&` 综合判断
- `switch` 语句中某个 `case` 分支末尾漏写 `break`，导致执行完当前功能后"穿透"到下一个 `case`，同时执行了两个本不该一起触发的功能
- 队列的 `enqueue` 函数中，错误地在把 `tail` 指向新节点后紧接着又 `free` 掉了同一块内存，导致 `tail` 变成悬空指针（use-after-free）
